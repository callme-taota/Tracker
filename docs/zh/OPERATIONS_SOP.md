# 运维与变更 SOP

## 目的

本文件用于把 feature flag 驱动的更新流程固化成低摩擦、可重复执行的操作规范。

## SOP 模板

### 1. 立项

- 定义本次变更
- 定义 legacy 路径
- 定义 flag key 和变体
- 定义成功指标与回滚触发条件

### 2. 实现

- 新代码路径必须挂在 flag 后面
- 保留旧逻辑不动
- 能补测试时，至少覆盖控制组与新路径求值
- 同步更新 `FEATURE_FLAGS.md`

### 3. 验证

- 先用请求级 override 做本地验证
- 再在非生产 channel 或单独 ring 验证
- 确认只有允许暴露的 flag 才会出现在 Web 快照中

### 4. 灰度

- 新路径权重初始设为 0
- 按受控步长逐步提高
- 观察日志、任务执行结果、API 错误率与前端回归

### 5. 回滚

- 优先使用 `TRACKER_FLAG_OVERRIDES`
- 降低新变体权重
- 必要时回滚构建版本
- 记录事故与最终缓解手段

### 6. 清理

- 将默认值切到胜出变体
- 观察窗口结束后删除败选路径
- 删除 flag 与相关文档项

## 最小检查表

- 开关已定义
- 旧路径仍保留
- 回滚方法已写明
- 观察指标已确定
- 清理责任人已指定
